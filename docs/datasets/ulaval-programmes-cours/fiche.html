Pourquoi ce jeu est intéressant

Cette fiche documente une intégration pédagogique de données institutionnelles de l’Université Laval structurées dans un dépôt privé. Elle ne sert pas à redistribuer les lignes de données. Elle sert à enseigner comment valider un import sensible : vérifier les comptes, les clés, la provenance, les droits et les limites de publication.

Le jeu est utile parce qu’il place les étudiants et étudiantes devant une situation fréquente en science des données appliquée : les données sont utiles, structurées et vérifiables localement, mais leur republication publique n’est pas automatiquement autorisée. C’est une bonne fiche pour enseigner la différence entre source officielle, compilation indépendante, validation reproductible et diffusion publique.

Question d’analyse : comment produire une validation statistique et méthodologique utile sans publier des lignes privées ni laisser croire à une approbation officielle?

Avertissement juridique et institutionnel

Cette intégration est une compilation indépendante et non officielle. Elle n’est pas un produit officiel ou approuvé par l’Université Laval.

Aucune licence ouverte explicite n’a été identifiée pour les données sources dans le paquet privé validé localement. Les CSV privés et les PDF sources ne sont pas redistribués dans Données bleues. Une validation institutionnelle ou juridique est nécessaire avant toute republication publique à grande échelle.

Ce document ne constitue pas un avis juridique.

Ce qui peut être enseigné

Cette fiche est moins un jeu de données à explorer publiquement qu’un cas d’étude sur la responsabilité. Les apprentissages les plus importants sont :

  1. conserver les codes comme chaînes de caractères;
  2. valider l’unicité des clés;
  3. conserver source_id et page_source;
  4. distinguer validation locale et republication publique;
  5. documenter les informations non vérifiées avec Je ne sais pas.;
  6. garder les PDF sources hors du dépôt public;
  7. éviter de transformer une valeur manquante ou non quantifiée en zéro.

Activité courte

En 30 à 45 minutes, lire les résumés de validation, identifier les clés de chaque fichier core et expliquer pourquoi les champs source_id et page_source doivent rester présents.

Activité longue

En 2 à 3 heures, produire un rapport méthodologique local qui résume les contrôles, les droits et les limites sans publier les lignes des CSV privés.

Code R minimal

À exécuter depuis la racine du projet. Si la source privée est absente, le script produit un résumé public indiquant que la validation locale n’a pas pu être faite.

# Load libraries
library(dplyr)
library(readr)

# Optional: point to the private source before running
# Sys.setenv(DONNEES_ULAVAL_SOURCE = "/chemin/local/source-ulaval-privee")

source("datasets/ulaval-programmes-cours/preparation.R")

resume <- read_csv(
  "data/processed/ulaval-programmes-cours/resume_ulaval_programmes_cours.csv",
  show_col_types = FALSE
)

fichiers <- read_csv(
  "data/processed/ulaval-programmes-cours/resume_fichiers_ulaval.csv",
  show_col_types = FALSE
)

resume |>
  select(source_found, validation_status, n_core_expected_rows, n_ges_expected_rows)

fichiers |>
  select(dataset_id, phase, observed_rows, keys_unique, protected_fields_present)

Limites et précautions

  • Les CSV privés ne sont pas inclus dans le dépôt Données bleues.
  • Les PDF sources ne sont pas redistribués.
  • Les résumés publics ne remplacent pas le registre privé des sources.
  • La source privée validée localement n’est pas un produit officiel approuvé par l’Université Laval.
  • Les valeurs numériques ne doivent pas être modifiées.
  • Les cellules non quantifiées, notamment en portée 3 GES, ne doivent pas être converties en zéros.
  • La réutilisation publique à grande échelle exige une validation institutionnelle ou juridique. Pour cette autorisation, je ne sais pas.
