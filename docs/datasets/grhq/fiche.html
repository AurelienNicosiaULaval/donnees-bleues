Pourquoi ce jeu est intéressant

La GRHQ est un bon jeu pour enseigner une idée importante en données spatiales : avant de lire une couche géométrique, il faut comprendre l’index, le format, l’unité de téléchargement et la taille implicite des fichiers. La fiche ne transforme donc pas la GRHQ en simple CSV. Elle prépare l’index officiel qui sert à choisir une unité hydrographique, puis elle documente les ressources spatiales détaillées disponibles.

Cette approche est adaptée à un cours de science des données parce qu’elle montre un vrai flux de travail : consulter les métadonnées, choisir un périmètre raisonnable, éviter de télécharger tout le Québec, puis seulement ensuite passer à sf, aux cartes et aux jointures spatiales.

Ce que représente une ligne

Dans la table préparée, une ligne représente une unité de téléchargement de l’index GRHQ. Ce n’est pas une rivière, un lac, un bassin versant, une jonction ou une surface hydrographique.

Variable Rôle
bloc Identifiant de l’unité de téléchargement dans l’index
region_hydrographique Région hydrographique extraite du bloc
partie Numéro de partie lorsque la région est fractionnée
is_split_unit Indique si l’unité est une partie d’une région
unit_kind Type d’unité de téléchargement
zone Libellé source de la zone
fgdb_url URL du fichier FGDB correspondant

Cette distinction est essentielle. L’index sert à décider quoi télécharger. Les analyses de longueur de cours d’eau, de surfaces hydrographiques ou de connectivité du réseau exigent ensuite de lire une géodatabase détaillée.

Lecture statistique

La GRHQ est un référentiel, pas un tableau d’observations indépendantes. Une bonne utilisation pédagogique suit cet ordre :

  1. lire l’index;
  2. choisir une unité de téléchargement;
  3. documenter le format et la projection;
  4. lire seulement la couche nécessaire;
  5. interpréter les résultats comme des objets géographiques, pas comme un échantillon statistique ordinaire.

La page MRNF indique que le produit vectoriel est offert en FGDB, avec système de projection CCL, à une échelle de 1/20 000 à 1/50 000 et une précision de 4 à 10 m en planimétrie. Ces informations doivent être conservées dans toute analyse cartographique.

Activité courte

En 30 à 45 minutes, lire l’index préparé, choisir une unité GRHQ et justifier ce choix sans télécharger tout le référentiel.

Activité longue

En 2 à 3 heures, préparer un plan d’analyse spatiale : choisir une unité, documenter le format FGDB, lister les couches attendues et proposer une jointure avec un autre jeu environnemental.

Code R minimal

À exécuter depuis la racine du projet.

# Load libraries
library(dplyr)
library(readr)

# Prepare official metadata and download index
source("datasets/grhq/preparation.R")

# Import prepared index
index_grhq <- read_csv(
  "data/processed/grhq/grhq_index_telechargement.csv",
  show_col_types = FALSE
)

# Summarize available units
index_grhq |>
  count(unit_kind, sort = TRUE)

# Select one unit before downloading a geodatabase
unite_choisie <- index_grhq |>
  filter(bloc == "08")

unite_choisie |>
  select(bloc, zone, fgdb_url)

Limites et précautions

  • L’index préparé ne contient pas les géométries hydrographiques détaillées.
  • Télécharger tout le référentiel peut être inutilement lourd pour un laboratoire.
  • Une ligne de l’index n’est pas une entité hydrographique.
  • Les analyses de longueur, surface, densité ou connectivité exigent la lecture d’une couche spatiale détaillée.
  • Les résultats cartographiques doivent documenter la projection, l’échelle et les simplifications éventuelles.

Extensions

  • Lire une FGDB avec sf::st_read() après avoir choisi une unité.
  • Comparer le WMS simple et le WMS détaillé.
  • Joindre des stations de qualité de l’eau à une unité GRHQ.
  • Construire une carte des unités de téléchargement à partir du SHP de l’index.
  • Discuter la différence entre référentiel spatial et échantillon statistique.
